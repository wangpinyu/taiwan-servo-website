# 產品頁架構規範

更新日期：2026-07-06

本文件定義產品頁本機 preview 與後續後台上架時的共用頁面架構。原則是保留正式網既有 UIUX，只整理 CKEditor 可控內容與 `產品規格詳情` 模組。

## 後台可編輯範圍

### 高自由度可編輯

- 產品頁 CKEditor 主內容區，主要是 `tw_specifications`。
- 本機 preview 中新增或調整的 `產品規格詳情`、模組標題、規格表、下載連結與 CTA，未來主要會映射到此區。

### 結構化可編輯但非自由排版

- 產品標題。
- 分類。
- SEO 欄位。
- 代表圖。
- 圖片欄位。

這些欄位可以編輯，但不適合用來承載複雜版型。

### 模板鎖死或不應由本輪處理

- 側邊 `介紹` 標籤。
- 全站導覽。
- 側欄分類框架。
- footer。
- 浮動聯絡按鈕。
- 部分產品頁固定版型。

本機 preview 可以用來檢查這些區塊如何影響視覺，但本輪不把它們視為可自由改版區。

## 標準模組順序

產品主內容建議順序：

1. 主內容區
2. 產品系列
3. 產品規格詳情
4. 應用領域
5. 技術資料下載

如果頁面沒有明確 `產品系列`，但有 `應用領域` 或 `技術資料下載`，`產品規格詳情` 可插入在 `應用領域` 前。若沒有既有規格模組或官方來源，不自動補寫。

## 模組命名規則

- 產品卡片、系列、型號導覽類：`產品系列`
- 規格表、型號矩陣、技術比較類：`產品規格詳情`
- Applications、Industry Applications、推薦應用、應用場景類：`應用領域`
- Downloads、相關下載、技術資料、文件下載類：`技術資料下載`

可保留的合理內容模組：

- `核心技術能力`
- `產品特色`
- `選型建議`
- 其他品牌或產品類別有明確內容目的的模組

遇到無法判定的標題時，不自動改名，列入人工審查報告。

## 產品規格詳情要求

- 必須位於 `產品系列` 下方。
- 不放產品圖片，避免與 `產品系列` 圖片重複。
- 使用 `<table>` 呈現規格，不使用 div 偽表格。
- 表頭保留官方欄位與單位。
- 型號或 Part Number 欄建議 sticky first column。
- 表頭建議 sticky。
- 手機版橫向捲動要有視覺提示。
- Accordion 必須有明確展開 / 收合控制。
- 下載連結分類清楚。
- 來源不足不得補假資料。

## CTA 規則

- 規格模組或頁尾至少要有可見詢問入口。
- 優先沿用既有詢問清單或聯絡流程。
- 若無法自動帶入型號，該限制寫入報告，不在前台顯示 TODO。

## SEO 規則

- 每頁一個 H1。
- 模組標題使用合理 H2/H3。
- 保留 canonical、title、meta description、breadcrumb。
- 不新增假價格、庫存、評論或評分。
- 只有可見 FAQ 才能加 FAQ schema。
- 重要文字內容使用可爬取 HTML。

## 本機 preview 與正式上架關係

本機 preview 是優化與審查基底。流程為：

1. 在本機 mirror 調整頁面與規格模組。
2. 執行 `npm run validate`。
3. 透過 AI agent review 與 GitHub PR 審查。
4. 本機確認後，再另開部署階段處理後台保存或伺服器覆蓋。

本文件不授權直接操作後台或正式伺服器。
